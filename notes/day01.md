# Day 1：从脚本到可测试的 Python 工具

## 1. 今天要理解什么

### 模块和包

- 一个 `.py` 文件通常是一个模块。
- 包是组织多个模块的目录，通常包含 `__init__.py`。
- `src/llm_tools_demo/calculator.py` 是模块。
- `src/llm_tools_demo/` 是包。

使用包结构可以减少导入混乱，也方便测试、复用和发布。

### 函数的职责

函数应该只承担一个清晰职责。计算器可以拆成：

1. 接收操作符和两个数字
2. 验证操作符
3. 执行计算
4. 返回结果或抛出明确异常

函数不应该同时负责用户输入、打印结果、读写文件和业务计算。

### 类型注解

```python
def add(left: float, right: float) -> float:
    return left + right
```

类型注解能帮助编辑器、静态检查工具和其他开发者理解接口，但 Python 默认不会在运行时自动阻止错误类型。

### 异常

出现无法正常完成的情况时，抛出明确异常：

```python
if right == 0:
    raise ZeroDivisionError("除数不能为 0")
```

不要用一个宽泛的 `except Exception` 悄悄吞掉所有错误。上层调用者需要知道操作为什么失败。

## 2. 为什么不能直接使用 eval

下面的代码会把用户输入当成 Python 程序执行：

```python
result = eval(user_input)
```

用户输入不一定只是算式，也可能包含读取文件、执行系统命令或访问程序内部对象的代码。对于计算器，应只接受白名单中的操作符，并由程序调用对应函数。

核心原则：

> 数据只能作为数据处理，不能在未经严格限制时作为代码执行。
